## What is fixed

The recipe preserves the runtime command and tuning I accepted: B12X GDN decode, linear and MoE backends, InstantTensor loading, NVFP4 weights through `modelopt_mixed`, MTP speculation at depth 3, GPU utilization `0.80`, four sequences, and a 4,096-token batch budget.

Two settings deserve attention because they are not interchangeable with defaults.

The PLE tables live on disk. `--additional-config '{"ple_table_memory":"disk"}'` sends the roughly 26.8 GiB of n-gram tables to the B12X io_uring `DiskTable`, which reads rows straight out of the checkpoint's safetensors by byte offset. Those tables never occupy VRAM or host DRAM, which is what makes the model fit on a unified-memory node. The consequence is that the published model directory must stay readable on local storage for the entire life of the process, not just during load, and the loader must be `instanttensor`.

The context comes from a YaRN override. The checkpoint declares `max_position_embeddings` 262,144 with `rope_type` `default`, so the 1,048,576-token window is a 4x override applied through `--hf-overrides`. The override keeps `mrope_section` and `mrope_interleaved` because `get_rope()` only preserves M-RoPE, which the vision position ids need, when `mrope_section` is present. Serving this at 1M tokens also requires vLLM `5a70cefff7e0` or later: earlier revisions did not pass the override into the MTP draft model, so the draft stayed at 262,144 and rejected a full-length prefill.

This is the LWS configuration I run. The Docker target uses the same engine definition, but I have not run it on two separate hosts.

The [deployment benchmark guide](/vllm-multiarch-oci/guides/benchmark-deployment/) explains how to run the benchmark against another deployment.

## Before applying output

- Each GPU node needs at least 130 GiB free on the model path. The checkpoint's tensor payload is about 99 GiB and it stays on disk for the life of the process.
- For Kubernetes, complete the <a href={`${import.meta.env.BASE_URL}guides/cluster-prerequisites/`}>cluster prerequisite checklist</a> and confirm the NVIDIA runtime, LWS controller, CNI, Multus, and RDMA allocator are ready.
- For Docker, synchronize the model on both hosts before starting either serving container. Start rank zero first, then let the worker's rendezvous check succeed before its headless server starts.
- Stop a GB10 serving container gracefully with a 120-second timeout. Long kernel execution is not grounds for force-killing a GPU process.
- A digest-qualified latest image is newer, not equivalent to the validated recipe image. Selecting it changes the validation status shown by the generator.

Published images are built from pinned fork revisions of [`local-inference-lab/vLLM`](https://github.com/local-inference-lab/vllm) and [`local-inference-lab/B12X`](https://github.com/local-inference-lab/b12x), not from their upstream branches. A revision alone does not say which proposed changes it carries, so this page lists them.

A change reaches the build in one of two ways. It is either already merged into the pinned fork revision, or it is applied to the pinned source at build time from a patch in this repository. Both are recorded below, and the same list is written into the image's `org.opencontainers.image.description` label.

## vLLM

Pinned at [`3ab11fdec715`](https://github.com/randomvariable/vllm/commit/3ab11fdec7151d043bdbd994fc8f1b2810797fb8), branched from [`local-inference-lab/vllm`](https://github.com/local-inference-lab/vllm) `dev/karmic-kraken`.

- **Bounded shared-memory broadcast waits** — no upstream pull request
  - Merged into the pinned revision (1 commits).
  - One commit, the adaptive-spin commit ce5f4148d4 of local-inference-lab/vllm#800, replayed on top of the prefetch commit. #800 now carries four commits and the other three are not part of this lock, so the entry names the pull request rather than claiming it in full. This base uses FlashInfer's CSF source/block APIs rather than the removed CsfScalePlanes API.
- **Run the fused MXFP4 DSA indexer path** — no upstream pull request
  - Merged into the pinned revision (1 commits).
  - FlashInfer main replaced the standalone MXFP4 score/select API with one fused plan/run call, so the DeepSeek V4.1 indexer takes it in both the forward path and the preparation callback. Scoring, top-512 selection and logical ordering now happen in one prepared run, which is also what the upstream fused implementation measured at a 37.26% median reduction against the staged route on SM120.
- **Advisory disk row-cache prefetch for Qwen4Exp PLE and DeepSeek V4.1 Engram** — no upstream pull request
  - Merged into the pinned revision (1 commits).
  - One switch, VLLM_PLE_PREFETCH=1, warms the host row cache ahead of the lookup through the pinned FlashInfer's DiskTable.prefetch and the ple_hash.host and engram.host row-id helpers.
- **Prometheus metrics for the b12x row cache and prefetch** — no upstream pull request
  - Merged into the pinned revision (7 commits).
  - Counters for hits, misses, residency, pool bytes and the prefetch queue, served on /metrics by vllm/v1/metrics/b12x_row_cache.py. The b12x caches are sampled on a daemon thread, never on the step path: reading them inline cost a 14 us median and a 3.6 ms worst case against the prefetch worker's lock, where the published snapshot costs 0.6 us. Totals are reported whether or not VLLM_PLE_PREFETCH is set, because the cache serves synchronous lookups either way.
- **Resolve FlashInfer scale-swizzle intrinsics** — no upstream pull request
  - Applied at build time by `third_party/vllm_b12x_intrinsics_reference.patch`.
  - Use intrinsics.reference for NVFP4 and MXFP4 linear weight preparation with the pinned FlashInfer.
- **Initialize pin-memory support after torch helpers** — no upstream pull request
  - Applied at build time by `third_party/vllm_pin_memory_import_order.patch`.
  - Fix the lunar CPU-platform circular import exposed by the image CLI smoke.
- **Rewrite flash_attn.cute imports to vllm.vllm_flash_attn.cute** — no upstream pull request
  - Applied at build time by `third_party/vllm_flash_attn_cute_namespace.patch`.
  - Packaging repair for this builder's symlink install path, which skips the import rewrite the upstream CMake copy performs. It carries no upstream change.

## Keeping this list honest

`scripts/vllmb12x-included-changes.py --check` fails when this page, the README table, or the image description no longer matches the ledger, and when the recorded patch series no longer matches the patches Bazel applies.

`scripts/vllmb12x-included-changes.py --verify --clone-root <directory>` goes further and checks the ledger against the fork history: a pull request is integrated by replaying its commits, so the command asserts that every commit of every listed pull request is present in the pinned revision, and that the recorded commit count still matches.
